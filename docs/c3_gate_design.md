# C3 실험 설계: 비정상 목적지별 수요 + 예측 정보 + 출발 시점(화물 확정) 결정 (research/rl)

작성 2026-11-02. 기여 C3의 근거를 만드는 실험이다. 배경은 [stream_rl_research.md](stream_rl_research.md) 5.6–5.9절
(현재 행동 공간에서 한 단계 개선이 이미 천장, 사후 최적과의 남은 격차 6–8%, 도어 막힘 약 27%)과
[literature_scan_stream_rl.md](literature_scan_stream_rl.md) 3.5절(예측·합적 출발 시점 문헌)에 있다.

## 0. 질문과 가설

목적지별 수요가 시간에 따라 바뀌고 그 예측을 쓸 수 있을 때, 출발 시점까지 정하는 정책이 예측의 가치를 가져가는가?

| 가설 | 내용 | 판정 지표 |
|---|---|---|
| H1 | 수요 변동이 클수록 예측 정보의 가치가 커진다 | 정보 가치 = 1 − J(정보 있음) / J(I0) |
| H2 | 출발 시점 결정은 예측과 함께 쓸 때 효과가 크다 | 결정의 이득이 정보 수준에 따라 커지는가 |
| H3 | 학습 정책은 예측 오차에 Rollout보다 강하다 | σ에 따른 성능 저하 기울기 |
| H4 | 학습 정책이 튜닝한 시간·수량 임계(TQ) 규칙을 넘는다 | 짝지은 Wilcoxon |

## 1. 환경 변경 (0단계, 구현 완료)

### 1.1 비정상 수요 (`crossdock_solver/stream/demand.py`)

- 전체 도착률 λ(t) = λ̄ (1 + A sin(2πt/P + φ₀)), 비동차 포아송 과정을 thinning으로 생성(`CrossDockStream._interarrival`).
- 목적지 비중 w_d(t) ∝ w_d (1 + A_d sin(2πt/P + φ_d)), 합이 |D|가 되도록 정규화. 병행 트럭 화물량은 도착 시각의 w_d(t)로 뽑는다.
- 위상: φ₀는 무작위, φ_d는 같은 간격(2π/|D|)으로 엇갈리게 두고 무작위 오프셋·순서 → 목적지마다 피크 시각이 다르다.
- 설정 `StreamConfig(amplitude=A, dest_amplitude=A_d, period_sla=P)`(P는 SLA 단위, 기본 4). λ̄는 기존처럼 부하 ρ로 정하므로 평균 부하는 같다.
- A = A_d = 0이면 기존과 같은 난수 경로를 탄다(시설 생성의 위상 난수는 기존 난수 뒤에 뽑음).

### 1.2 예측 정보 수준

| 수준 | Rollout의 미래 표본 | 구현 |
|---|---|---|
| I0 장기 평균만 | 정상 포아송, 고정 w_d | `StationaryDemand` |
| I1 오차 있는 예측 | 실제 곡선 × exp(σe(t) − σ²/2), e는 목적지별 AR(1)(ρ = 0.9, 격자 = 트럭당 평균 작업량), 위상 오차 옵션 | `NoisyDemand` |
| I2 분포 알고 실현값 모름 | 실제 곡선 | `TrueDemand` |
| I3 실제 미래 | 실제 미래 그대로 | `fork(oracle=True)` |

- `fork(..., demand=모형)`이 미래 도착을 그 모형에서 다시 뽑는다. `RolloutPolicy(demand=...)`로 지정.
- 정책이 볼 수 있는 예측량: `DemandModel.expected_units(t0, t1)`(목적지별 예상 유입 화물). TQ 규칙·RL 특징(2–3단계)에 쓴다.

### 1.3 화물 확정(출발 시점) 결정

- 기존: 운송 트럭은 적재 단계 시작(CLAIM 사건) 때 무조건 즉시 화물을 확정한다.
- 변경(`max_extensions > 0`): CLAIM 사건이 결정 시점이 된다(`env.needs_claim`, `env.resolve_claim(extend)`).
  연장하면 `extension_work`(기본 0.25) × 트럭당 평균 작업량만큼 도어에서 기다린 뒤 다시 CLAIM 사건이 온다. 그 사이 하역된 d행 화물도 이번 트럭이 가져간다.
  연장은 최대 `max_extensions`회, 이후 자동 확정.
- 정책 인터페이스: `policy.claim(env, truck) -> bool`. 없으면 즉시 확정(기존 정책 모두 그대로 동작). `sim.step(env, policy)`가 두 결정을 나눠 처리한다.
- Rollout: 확정 / 연장 두 행동을 같은 fork·공통 난수로 비교한다(`RolloutPolicy.claim`). 미래 시뮬레이션 안의 기본 정책은 즉시 확정.
- 적재 용량은 아직 없다(연장의 손해는 도어 점유와 리드타임뿐). TQ 규칙 비교 때 용량 C 도입 여부를 다시 판단한다.

**제약**: 사후 최적 모형(`hindsight.py`), 롤링 호라이즌, RL 특징(`rl.py`)은 연장 결정과 비정상 수요를 모른다. 0–1단계에서는 Rollout만 쓴다.

**테스트** (`tests/test_stream.py` 끝의 C3 묶음 8개): 비중 합·평균 도착률 보존, 도착이 곡선을 따름(고·저 반주기 도착 비 1.9–2.6),
정상 모형 fork = 기존 fork, 잡음 예측의 시드 고정·불편성, `expected_units`와 실제 유입 일치(10% 이내),
즉시 확정 정책 = 결정 없는 모형(목적값 동일), 연장 시 확정 시각과 화물 범위, 확정 대기 중 fork와 Rollout 확정 결정.
기존 결과 재현: FCFS-VAA(S·M)와 Rollout의 목적값이 변경 전과 비트 단위로 같음을 확인했다.

## 3. 결과

1단계 결과는 `outputs/stream_c3_gate_summary.txt`(원자료 `outputs/stream_c3_gate.jsonl`)에 있고, 판정은 아래에 옮긴다.

### 3.1 1단계 게이트 (2026-11-02): **실패 → C3 중단**

S, ρ = 0.7, skewed, C3 tuning 풀 12개 스트림. 값은 J/work, 이득은 스트림별 1 − J_좋은쪽 / J_나쁜쪽의 평균이다.

| 설정 | A = 0 | A = 0.6 |
|---|---:|---:|
| FCFS-VAA | 1.587 | 1.624 |
| Rollout-I0, 연장 없음 | (= I2) | 1.439 |
| Rollout-I2, 연장 없음 | 1.365 | 1.438 |
| Rollout-I3, 연장 없음 | 1.296 | 1.374 |
| Rollout-I0, 연장 최대 4회 | (= I2) | 1.455 |
| Rollout-I2, 연장 최대 4회 | 1.337 | 1.419 |
| Rollout-I3, 연장 최대 4회 | 1.278 | 1.371 |

| 비교 | 이득 | 좋은 스트림 | p |
|---|---:|---:|---:|
| 정보 I0/I2 → I3, A = 0 (정적 정보 가치) | +5.0% | 12/12 | 0.0005 |
| 정보 I0 → I3, A = 0.6 | +4.5% | 12/12 | 0.0005 |
| 곡선을 앎 I0 → I2, A = 0.6 | +0.1% | 7/12 | 0.57 |
| 실현값을 앎 I2 → I3, A = 0.6 | +4.4% | 12/12 | 0.0005 |
| 확정 결정, A = 0, I2 | +2.1% | 11/12 | 0.001 |
| 확정 결정, A = 0.6, I2 | +1.3% | 9/12 | 0.034 |
| 확정 결정, A = 0.6, I0 | −1.0% | 5/12 | 0.27 |
| 확정 결정, A = 0.6, I3 | +0.3% | 8/12 | 0.34 |
| 곡선을 앎 I0 → I2, 확정 결정 있음, A = 0.6 | +2.4% | 9/12 | 0.021 |

판정: G1 +4.5% < 2 × 5.0%(실패), G2 +1.3% < 3%(실패). 미리 정한 규칙대로 C3를 중단한다.

해석

- **수요 곡선을 아는 것의 가치가 거의 없다(+0.1%).** 진폭 0.6, 주기 4 SLA의 물결에서도 FCFS-VAA는 2.3%만 나빠지고, 정보 가치는
  거의 모두 실현값(다음 트럭이 언제 오는가, +4.4%)에서 나온다. 정적 환경(5.6절, 이번 풀 +5.0%)과 같은 크기다. 곡선은 결정 구간(1 SLA)보다
  천천히 변해서 현재 상태(야드·대기 화물)에 이미 반영되는 것으로 본다.
- **확정 결정의 이득은 작지만 유의하다(+1–2%).** 정적 수요에서 더 크고(+2.1%), 미래를 다 알면 거의 사라진다(+0.3%). 연장 비율은 운송
  트럭의 5–13%이고, 운송 트럭당 화물량은 바뀌지 않으며(78–79), 도어 점유는 조금 늘었다(0.80 → 0.82–0.89 작업량). 즉 합적을 늘리는
  효과가 아니라 불확실성 아래 확정을 조금 늦추는 보험 성격이다. 적재 용량이 없는 모형이라 합적의 이점이 원래 작다.
- **예측과 확정 결정의 상호작용은 있다.** 확정 결정이 있을 때만 곡선 정보가 쓸모 있고(+2.4%, p = 0.021), 틀린 정보(I0)로 연장하면
  오히려 나빠진다(−1.0%). 가설 H2와 같은 방향이지만 크기가 기준(3%)에 못 미친다.
- 설정 하나(S, ρ = 0.7, skewed)의 결과다. 주기·진폭·연장 길이·적재 용량을 바꾸면 달라질 수 있으나, 게이트 실패 뒤 조건을 바꿔
  다시 찾는 것은 사후 탐색이 되므로 하지 않는다. 다시 연다면 적재 용량과 출고 마감(시간표)처럼 **모형 현실성 근거가 먼저 있는 변경**으로
  사전 등록한 뒤 연다.

결론: "비정상 수요 + 예측 + 확정 시점"을 넣어도 한 단계 Rollout이 쓸 수 있는 여지는 1–2%이고, 정보 가치는 정적 환경과 같다.
이 결과는 C2(한 단계 개선의 포화, 정보 가치 분해)를 보강하는 음성 결과로 쓴다.
