## 1. 코드 대조로 확인된 오류·누락

| # | 항목 | 원고 | 코드 실제 | 상태 |

| 1.6 | 목적지 수 | $(|I|,|D|,|M|)$만 제시 | $|D|=|I|+|F|$, $|M|=|I|$ | 🟠 관계 미명시 |
| 1.7 | loose 수준 | none/medium/tight 3종 | 코드엔 `loose (0.10,1.00)`도 있음 (미사용) | 🟡 미사용 명시 필요 |

| 1.9 | 화물량 | "$[0,20]$ 균등 정수" | `integers(0,21)` → 0–20 | 🟢 정확 |

**1.4가 가장 심각했다.** $H$ 없이는 $\rho,\delta$가 무슨 뜻인지 알 수 없어
시간 제약 설계 전체가 해석 불가였다. → 2026-09-10 해결.

**기호 충돌 주의**: §3.1이 이미 $H_i=\sum_d h_{id}$(트럭 $i$의 총 처리량)를 쓴다.
지평을 $H=2\sum_{i\in I}H_i/|M|$로 정의하면 둘이 자연스럽게 연결되어 충돌이 아니라
일관된 표기가 된다. 다른 기호($\hat H$ 등)를 새로 도입하지 말 것.

## 2. 재작성 구조

현재 2문단(설계+측정)을 **3개 소절**로 나눈다. 분량은 9줄 → 약 20줄.

### 5.1 인스턴스 생성

읽는 순서를 **"크기 → 화물 → 시간 → 공간"** 으로 고정하고, 값은 표로 뺀다.

- 규모 정의에 $|D|=|I|+|F|$, $|M|=|I|$ 관계를 한 문장으로 명시
- 화물 분포는 `uniform`만 사용함을 밝히고, 나머지 2종은 DQN 학습에만 쓰였음을 각주
- **$H$를 정의**: "시간 제약이 없을 때의 총 작업완료시간 추정치로,
  총 처리량을 도어 수로 나눈 뒤 2를 곱해 얻는다"
- $\rho$(도착 산포)와 $\delta$(납기 여유)의 **의미를 한 문장씩** 부여

### 5.2 시간 제약 수준

none/medium/tight의 **설계 의도**를 밝힌다.

- none = 기존 모델로 환원되는 대조군 (원 모델과 직접 비교 가능)
- medium/tight는 $\rho$↑·$\delta$↓ 두 방향으로 동시에 어려워짐
- tight에서 지연이 불가피해져 목적식의 납기지연 항이 실제로 작동함

### 5.3 측정 프로토콜

- seed 3분할의 **이유**(학습 정책·$\lambda$의 시험집합 오염 방지)를 한 문장으로
- 20개 × 5회의 **이유**(인스턴스 간 난이도 편차 / 알고리즘 무작위성)
- "인스턴스별 평균 후 Wilcoxon"의 **이유**(반복 실험은 독립이 아님)
- $\Delta_{bo}$를 쓰는 **이유**(대형에서 CP-SAT 기준해가 없음)

## 4. 그림 제안

현재 그림 4개는 **전부 결과 그림**이고 **문제·설계를 보여주는 그림이 하나도 없다.**
독자가 "이 문제가 어떻게 생겼는지" 그림으로 볼 수 없는 것이 이해도를 떨어뜨리는
가장 큰 원인이다. 우선순위 순으로 제안한다.

### 🥇 그림 A — 병행 트럭 처리 흐름 (§3.1, 문제 정의)

**가장 필요하다.** 논문의 핵심인 부분 하역 전환 과정이 지금은 글로만 설명된다.

한 대의 병행 트럭에 대해 시간축을 그리고 다음을 순서대로 표시한다.

```
도착(r_i) → 진입(DE_i) → 부분 하역(유지 목적지 d 제외) → [타 트럭 화물 이송 대기]
          → 유지 화물 + 이송 화물 적재 → 출차(DL_i) → 완료(C_i)
```

같은 그림에 출고 트럭 한 대를 아래 레인으로 그려 $S_f=\max(\text{도어 가용},
\text{목적지 준비}, r_f)$ 세 항이 어디서 오는지 화살표로 잇는다.
→ §3.1의 타이밍 규칙 서술 대부분을 그림이 대신한다.

### 🥈 그림 B — 시간 제약 3수준 모식도 (§5.2)

$\rho$와 $\delta$가 무엇인지 글로는 잘 전달되지 않는다.
가로축을 $[0,H]$로 두고 세 수준을 3단으로 겹쳐 그린다.

```
none    |████████████████████████|   도착 전부 0, 납기 없음
medium  |▓▓▓▓▓▓|--------- 여유 0.60H ---------|
tight   |▓▓▓▓▓▓▓▓▓▓▓▓|---- 여유 0.35H ----|
         ↑도착 산포 ρH
```
→ "두 방향으로 동시에 어려워진다"는 설명이 한눈에 들어온다.

### 🥉 그림 C — 도어 배치 예시 (§5.1)

이번에 문제가 됐던 바로 그 부분. $100\times100$ 정사각형에 도어 6개를 점으로
찍고, 가까운 쌍과 먼 쌍의 이송시간을 각각 라벨로 붙인다(예: 1↔3 = 1.65,
4↔6 = 8.39). 원 모델의 I자형 일렬 배치를 옆에 작게 병치하면 대비가 명확하다.
→ "왜 랜덤 배치인가"(도어 배정이 실제로 성능을 가르게 하려고)가 즉시 전달된다.
