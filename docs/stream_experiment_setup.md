# 실험 환경: 연속 도착 크로스도킹 (research/rl 브랜치)

연구 질문, 한계 가설, 결과는 [stream_rl_research.md](stream_rl_research.md)에 있고, 이 문서는
실험 환경(모형, 파라미터, 목적식, 실험 설계, 비교 방법, 학습 설정, 계산 환경, 재현 방법)만 다룬다.

## 1. 시뮬레이터

코드: `crossdock_solver/stream/sim.py` (`CrossDockStream`), 설정 `crossdock_solver/stream/config.py`

정적 모형(JKIIE 원고)은 목적지마다 운송 트럭이 정확히 한 대이고(|I| + |F| = |D|) 트럭 집합이 한 번
주어지고 끝난다. 이 환경에서는 트럭이 끝없이 도착하므로 시간이 지날수록 |I| + |F| ≫ |D|가 되고,
목적지 하나를 여러 운송 트럭이 번갈아 맡는다.

| 요소 | 규칙 |
|---|---|
| 도착 | 포아송 흐름. 도착 트럭의 2/3는 병행 트럭(여러 목적지 화물 적재), 1/3은 빈 출고트럭 |
| 결정 시점 | 빈 도어가 있고 야드에 트럭이 있는 사건 시점(도착, 출발 직후) |
| 행동 | (야드 트럭, 빈 도어, 목적지) 하나를 고르거나 보류(HOLD). 후보 트럭은 야드 앞쪽 6대 |
| 병행 트럭 | 진입 → 유지 목적지 d를 뺀 화물 부분 하역(하역이 끝나는 시점에 그 도어에 대기 화물로 쌓임) → d의 운송 트럭으로 적재 → 출차 |
| 출고트럭 | 진입 → d의 운송 트럭으로 적재 → 출차 |
| 인계 규칙 | 운송 트럭은 적재 단계를 시작하는 순간, 이미 도킹한 트럭이 내렸거나 내리고 있는 d행 화물을 모두 가져가고, 그 화물의 하역 완료와 도어 간 이송이 끝날 때까지 도어에서 기다린 뒤 적재한다. 그 뒤에 도킹한 트럭의 화물은 다음 운송 트럭을 기다린다 |
| 도어 | 한 번에 트럭 한 대. 진입부터 출차까지 점유 |
| 정보 제한 | 정책은 도착한 트럭만 본다. Rollout의 상태 복제(`fork`)는 대기 중인 다음 도착 시각을 버리고 미래 도착을 새 난수로 다시 뽑는다(포아송 흐름이라 분포가 같다) |

## 2. 파라미터

| 항목 | 값 |
|---|---|
| 규모 (도어, 목적지) | S (6, 4), M (10, 6), L (16, 8). L은 학습에 쓰지 않고 일반화 평가에만 사용 |
| 상품 종류 | 3 |
| 화물량 (트럭 i, 목적지 d, 상품 k) | 정수 U[0, ⌊20·w_d⌋] |
| 수요 가중치 w_d | uniform: 모두 1 / skewed: 1/순위를 합이 \|D\|가 되도록 정규화한 Zipf형(한 목적지에 화물 최대 약 50%), 목적지 순서는 무작위 |
| 단위 처리시간 t_k | U{1..4} (스트림마다 고정) |
| 진입·출차 시간 | 트럭마다 U{1..5} |
| 도어 간 이송시간 | 도어를 100×100 평면에 무작위 배치, 유클리드 거리/10 (스트림마다 고정) |
| 명목 부하 ρ | 0.5, 0.6, 0.7 |
| 도착률 | ρ × 도어 수 / 트럭당 평균 작업량 |
| 트럭당 평균 작업량 | 진입·출차 6 + 병행 트럭 화물의 하역·적재(유지 화물 1/\|D\| 제외)를 트럭 유형 비율로 평균. 시험 스트림 평균 S 288, M 496, L 711 |
| 평균 도착 간격 | 약 64–99 (ρ = 0.7에서 S 68.6, M 70.9, L 63.5) |
| 트럭당 평균 화물량 | S 80, M 120, L 160 단위 |
| 납기 | 도착 시각 + SLA, SLA = 3 × 트럭당 평균 작업량 (S 864, M 1,488, L 2,132) |
| 납기지연 가중치 λ | 1 |

명목 부하는 순수 처리 작업량만 센다. 운송 트럭이 화물을 기다리며 도어를 점유하는 시간이 빠져 있어서
실제 도어 점유율은 더 높다(FCFS-VAA에서 ρ = 0.7일 때 0.85–0.99). ρ = 0.7의 L-uniform은 FCFS-VAA로도
대기열이 커지는 불안정 구간이다.

## 3. 목적식과 지표

**목적식(장기 평균).** 측정 구간의 트럭에 대해

    J = 화물 단위당 평균 리드타임 + λ × 트럭당 평균 납기지연

리드타임은 병행 트럭 도착부터 그 화물을 실은 운송 트럭 출발까지이고(유지 화물은 그 병행 트럭의 출발까지),
납기지연은 max(0, 출발 − 납기)이다. 정적 모형의 "총 작업완료시간 + λ·총 납기지연"을 연속 흐름으로 옮긴
형태이다. 규모가 다르면 시간 척도가 달라지므로 비교는 J를 트럭당 평균 작업량으로 나눈 **J/work**로 한다.

**보조 지표** (`StreamMetrics`, `experiments/stream_eval.py`)

| 지표 | 의미 |
|---|---|
| mean_lead, mean_tardiness | J의 두 성분 |
| mean_sojourn, mean_yard_wait | 트럭 체류시간, 도킹 전 야드 대기 |
| utilization | 도어 점유율(화물을 기다리는 시간 포함) |
| empty_outbound_rate | 화물 없이 떠난 출고트럭 비율 |
| undelivered_units | 시간 상한에서 아직 남은 측정 화물(있으면 상한 시각까지로 리드타임 계산) |
| hold_rate, decide_ms_mean/max | 보류 비율, 결정 1회 계산 시간 |
| cycle_wait, plan_ms_mean/max | Cyclic 방식만: 사이클이 다 모일 때까지의 대기, 사이클당 계획 시간 |

추가 진단(`experiments/stream_behavior.py`, 조정 집합): 운송 트럭이 도어에서 화물을 기다린 시간의 비중
(도어 막힘), 앞 트럭을 건너뛴 결정·규칙과 다른 목적지를 고른 결정의 비율, 목적지별 운송 트럭 비중과
화물 비중의 L1 거리.

**연속 비용 적립.** 시뮬레이터는 같은 비용을 시간에 따라 적립한다(시스템 안 화물량의 적분 / 트럭당 평균
화물량 + λ × 납기를 넘긴 체류 트럭 수의 적분). 긴 구간에서 이 합은 트럭 수 × J에 수렴하므로, RL 보상은
다음 결정까지 적립된 비용의 음수로 둔다.

## 4. 실험 설계

| 항목 | 설정 |
|---|---|
| 시드 풀 | train 100000+ (학습), tuning 200000+ (체크포인트·설계 선택), test 300000+ (최종 비교만) |
| 시험 격자 | 규모 3 × 부하 3 × 수요 2 = 18셀, 셀당 독립 스트림 5개 → 방법당 90개 |
| 시험 측정 구간 | 각 스트림의 200–1199번째 도착 트럭(1,000대). 앞 200대는 워밍업으로 제외 |
| 종료 조건 | 측정 트럭이 모두 떠나고 그 화물이 모두 배송될 때까지 도착을 계속 생성하며 진행(끝 효과 없음). 안전장치로 마지막 측정 트럭 도착 후 20 × SLA에서 중단 |
| 조정 집합 | S/M × 부하 3 × 수요 2 = 12 스트림, 측정 구간 100–499번째 |
| 학습 스트림 | S/M × 부하 3 × 수요 2에서 무작위 추출, 측정 구간 100–399(PPO) 또는 50–249(증류) |
| 통계 | 스트림별 J/work로 짝지은 양측 Wilcoxon signed-rank (`experiments/k1_stats.py`의 구현) |

## 5. 비교 방법

| 방법 | 내용 | 코드 |
|---|---|---|
| FCFS-VAA | 먼저 온 트럭을 빈 도어로. 병행 트럭은 자기 화물(처리시간)이 가장 많은 목적지를 유지하고 이송 거리 평균이 가장 작은 빈 도어를 쓰며, 출고트럭은 대기 화물이 가장 많은 목적지를 맡고 그 화물에서 가장 가까운 빈 도어를 쓴다 | `FCFSRulePolicy()` |
| FCFS-Backlog | 병행 트럭이 자기 화물 + 대기 화물 기준으로 목적지 선택 | `FCFSRulePolicy(backlog=True)` |
| Cyclic-VAA | 원 방법을 그대로 쓰기 위해 도착순 \|D\|대를 한 사이클(\|I_c\| + \|F_c\| = \|D\|)로 묶어 정적 인스턴스로 만들고 VAA로 계획. 계획 도어가 바쁘면 가장 가까운 빈 도어를 쓰고, 출고트럭은 같은 사이클에서 해당 목적지 화물을 실은 병행 트럭이 모두 도킹한 뒤 보낸다(유연 실행) | `CyclicPlanPolicy(iterations=0)` |
| Cyclic-GILS | 위와 같되 사이클마다 VAA-GILS 1,000회(논문 최종 엔진: 균등 선택, greedy 수락) | `CyclicPlanPolicy(iterations=1000)` |
| Cyclic-SA-RL5 | 같은 틀에서 사이클마다 원 논문의 SA-RL5(Extended-SA-RL5, 1,000회) | `CyclicPlanPolicy(solver="sa-rl5")` |
| Cyclic-CPSAT | 같은 틀에서 사이클마다 CP-SAT(10초, 1 worker, 해가 없으면 GILS) | `CyclicPlanPolicy(solver="cpsat")` |
| SPT-VAA | 앞 6대 중 처리시간(진입·출차 + 자기 화물 또는 가져갈 대기 화물)이 가장 짧은 트럭 먼저, 목적지·도어는 FCFS-VAA | `SPTRulePolicy()` |
| Random | 앞 6대 트럭·빈 도어·목적지 무작위, 보류 없음 | `RandomPolicy()` |
| Cyclic-GILS-strict | 같은 계획을 계획한 도어가 빌 때까지 기다리며 그대로 실행 | `execution="strict"` |
| RL-BC | FCFS-VAA를 모방한 정책망(행동이 FCFS-VAA와 같음) | `stream/rl.py` |
| RL-PPO | BC로 시작한 PPO v2, 조정 집합 기준 최선 체크포인트 | `outputs/stream_rl/ppo2_tau1.pt` |
| Rollout | 후보 행동마다 현재 상태를 8번 복제해 1 × SLA 동안 FCFS-VAA로 진행(공통 난수)하고, 적립 비용이 가장 작은 행동 선택. 후보 = 앞 트럭 × 모든 목적지, 다음 두 트럭의 규칙 행동, HOLD | `stream/rollout.py` |
| RL-API | Rollout의 결정을 DAgger로 증류한 정책망, 조정 집합 기준 최선 라운드(2) | `outputs/stream_rl/api.pt` |

사이클의 정적 인스턴스는 계획 시점 기준 상대 시각을 쓴다(모든 트럭 도착 완료이므로 release 0, 납기는 남은
SLA 여유). 처리시간은 그대로 보존하고, 도어가 이미 바쁘다는 정보는 정적 모형에 넣을 수 없어 빠진다.

## 6. 강화학습 설정

**정책망** (`DispatchNet`): 후보마다 24차원 특징을 공유 MLP(64-64, tanh)로 점수화하고 소프트맥스로 행동을
고른다. 특징은 다음과 같고, 시간은 트럭당 평균 작업량, 화물은 트럭당 평균 화물량으로 나누어 규모에 무관하게 했다.

| 묶음 | 특징 |
|---|---|
| 트럭 | 유형, 대기 시간, 납기 여유, 야드 내 순서, 해당 목적지 화물 비중, 총 처리시간, 유지 시 하역 시간, 해당 목적지 처리시간 |
| 목적지 | 대기 화물 처리시간, 가장 오래된 대기 화물의 나이, 아직 하역 중인 화물, 먼저 가져갈 운송 트럭 수, 마지막 출발 이후 시간, 수요 비중, 야드 트럭이 가진 해당 목적지 화물 |
| 도어 | 중심성(평균 이송시간), 대기 화물에서 이 도어까지의 가중 이송시간, 예상 적재 대기 시간 |
| 전역 | 야드 길이, 빈 도어 비율, 시스템 화물량, 1/\|D\| |
| 지시자 | 앞 트럭 여부, FCFS-VAA가 고를 행동 여부 |

가치망은 전역 상태 14차원(위 4개 + 야드 병행/출고 트럭 수, 야드 화물량, 대기·미하역 화물, 적재 전 도킹 트럭,
도킹 트럭의 남은 시간, 가장 오래된 화물 나이, 야드 대기 평균·최대)과 후보 특징의 평균·최댓값을 입력으로 쓴다.

| 학습법 | 설정 |
|---|---|
| BC 예열 | 학습 스트림 16개에서 FCFS-VAA 행동 수집, 40 epoch, 학습률 1e-3 |
| PPO v1 (커밋 df81e17) | 반복당 에피소드 8, 학습률 3e-4, 클리핑 0.2, 엔트로피 0.01, 할인 시간 척도 2 × SLA |
| PPO v2 | 반복당 에피소드 12, critic 예열 10회, 학습률 1e-4, 클리핑 0.1, 엔트로피 0, 할인 exp(−Δt / SLA), GAE λ 0.95, 미니배치 256, epoch 4, 250회(실제로는 정체 확인 후 중단) |
| Rollout 증류 | 라운드당 학습 스트림 16개(측정 구간 50–249), 1라운드는 교사 행동으로 진행(β = 1), 이후 β = 0.5로 학습자 행동 혼합(DAgger), 데이터 누적, 라운드마다 30 epoch, 학습률 1e-3, 6라운드 |

체크포인트는 20회 반복(PPO) 또는 매 라운드(증류)마다 조정 집합 12개 스트림의 평균 J/work로 고른다.

## 8. 재현 방법

```bash
python -m pytest -q tests/test_stream.py                                   # 시뮬레이터·fork·후보 인덱스 검증
python experiments/stream_rl_train.py --name ppo2_tau1 --tau-sla 1.0       # PPO v2 (train 학습, tuning 선택)
python experiments/stream_rollout_probe.py --samples 8 --horizon 1.0       # Rollout의 조정 집합 점수
python experiments/stream_api_train.py --name api --rounds 6 --episodes 16 # Rollout 증류(DAgger)
python experiments/stream_eval.py --workers 4                              # 시험 집합 평가(빠진 작업만 실행) + 요약
python experiments/stream_eval.py --sizes S,M --methods SPT-VAA,Random,Cyclic-SA-RL5,Cyclic-CPSAT  # 추가 기준(5.4절)
python experiments/stream_eval.py summary                                  # 요약만
python experiments/stream_cycle_quality.py                                 # 사이클 단위 품질(tuning 풀)
python experiments/stream_behavior.py                                      # 정책 행동 진단(조정 집합)
```

## 9. 예비 환경: 유한 동적 모형 (G0)

연속 환경 이전에 정적 모형을 그대로 두고 도착 시각만 실시간으로 드러나게 한 환경을 먼저 시험했다
(`crossdock_solver/dynamic/`, `experiments/dynamic_gate.py`, 결과 `outputs/dynamic_gate_summary.txt`).

| 항목 | 설정 |
|---|---|
| 인스턴스 | 정적 벤치마크(S, M) × 시간 제약 none/medium/tight, tuning pool 5개 × 도착 실현 2개 |
| 도착 불확실성 | r = max(0, 계획 도착 + N(0, (σH)²) + 지연 꼬리), low/medium/high = (σ, 지연 확률, 지연 평균) (0.02, 0.1, 0.05H) / (0.05, 0.2, 0.1H) / (0.08, 0.3, 0.2H) |
| 결정 규칙 | 트럭이 도착하는 순간 목적지·도어 확정, 출고트럭은 도어 대기열 끝에 추가 |
| 비교 | Random, StaticPlan, Greedy, Rolling-GILS(결정마다 200회 재최적화) 대 Hindsight(실현 인스턴스 GILS 1,000회) |

결과: StaticPlan도 Hindsight 대비 0.3–0.6%, Rolling-GILS 0.14–0.45%로 학습할 여지가 거의 없어서
연속 도착 환경으로 전환했다.

## 10. 검토가 필요한 설계 선택

- 명목 부하의 정의(도어 막힘 시간 제외)와 부하 수준 0.5–0.7의 선택
- Cyclic 방식의 유연 실행 보정(원 방법에는 없는 실행 규칙을 VAA-GILS에 공정하도록 추가함)
- 인계 규칙(도킹한 트럭의 화물만 가져가고, 하역 중인 화물은 기다림)과 운송 트럭 적재 용량 무제한 가정
- 화물 리드타임과 트럭 납기지연을 같은 가중치(λ = 1)로 더한 목적식
