# 연속 도착 크로스도킹에서 VAA-GILS의 한계와 강화학습 (research/rl 브랜치)

JKIIE 원고의 정적 모형(|I| + |F| = |D|, 한 번의 닫힌 배치, makespan + λ·납기지연)을
트럭이 끝없이 도착하는 운영 환경(|I| + |F| ≫ |D|)으로 옮겼을 때, VAA-GILS가 어디서
무너지는지 측정하고, 강화학습(RL)이 그 한계를 메우는지 실험한다.

> 결과 수치는 `outputs/stream_eval_summary.txt`(시험 집합)와 `outputs/stream_rl/`
> (학습·조정 기록)에 있다. 이 문서의 표는 그 파일에서 옮긴 것이다.

## 0. 예비 결과: 도착 시각 불확실성만으로는 학습할 여지가 없다 (G0)

먼저 정적 모형을 그대로 두고 트럭 도착 시각만 실시간으로 드러나게 했다
(`crossdock_solver/dynamic/`, `experiments/dynamic_gate.py`, tuning pool).
재계획을 전혀 하지 않는 StaticPlan도 사후 최적(Hindsight)보다 평균 0.3–0.6%만 나빴고,
Rolling-GILS는 0.14–0.45%였다. 무작위 정책은 10–35% 나빠서 배정 결정 자체는 중요하지만,
최적 배정이 도착 시각에 거의 영향을 받지 않는다. 이 설정에서는 RL이 개선할 여지가 0.5% 미만이므로
문제 구조 자체를 바꾸었다(아래).

## 1. 연속 도착 모형

모형, 파라미터, 목적식, 실험 설계, 계산 환경의 전체 내용은
[stream_experiment_setup.md](stream_experiment_setup.md)에 있다. 요약하면 다음과 같다.

- 트럭이 포아송 흐름으로 끝없이 도착하고(병행 트럭 2/3), 도어가 비면 정책이 (트럭, 도어, 목적지)를
  고르거나 보류한다. 병행 트럭의 부분 하역 → 운송 트럭 전환 구조는 정적 모형과 같다.
- 운송 트럭은 적재 시작 시점에 이미 도킹한 트럭의 해당 목적지 화물을 모두 가져가고, 하역·이송이 끝날 때까지 기다린다.
- 목적식은 J = 화물 단위당 평균 리드타임 + λ · 트럭당 평균 납기지연(λ = 1)이고, 규모 간 비교는 J/work로 한다.

## 2. VAA-GILS를 연속 흐름에 적용하는 방법

VAA-GILS의 해 표현은 "목적지마다 운송 트럭 정확히 한 대"이다. 원 방법을 바꾸지 않고 쓰려면
도착 순서대로 |D|대씩 묶어 한 사이클을 정적 인스턴스(|I_c| + |F_c| = |D|)로 만들고, 사이클마다
VAA 또는 VAA-GILS(1,000회, 논문 최종 엔진)로 풀어야 한다(`CyclicPlanPolicy`).

- `Cyclic-GILS-strict`: 계획한 도어가 빌 때까지 기다리며 계획대로 실행
- `Cyclic-GILS` / `Cyclic-VAA`(adaptive): 목적지와 순서는 계획을 따르되, 계획 도어가 바쁘면 가장
  가까운 빈 도어를 쓰고, 출고트럭은 같은 사이클의 해당 목적지 화물 병행 트럭이 모두 도킹한 뒤
  보낸다(정적 모형의 "운송 트럭은 이송 화물을 모두 기다린다"를 지키도록). VAA-GILS에 공정하도록
  추가한 실행 보정이다.

## 3. 한계 가설과 측정 지표

| 한계 | 메커니즘 | 측정 |
|---|---|---|
| L1 사이클 강제 | |D|대가 모일 때까지 계획을 못 함 | 사이클 형성 대기(`cycle_wait`) |
| L2 운송 빈도 경직 | 사이클마다 목적지별 운송 트럭이 정확히 1대 → 화물량과 무관하게 1/|D| | skewed 수요에서 비용 증가, 목적지별 운송 트럭 비중 대 화물 비중 |
| L3 정적 계획-실행 불일치 | 정적 모형은 모든 도어가 비어 있고 사이클 병행 트럭이 동시에 도킹한다고 가정 | strict 실행의 비용과 안정성 |
| L4 대리 목적식 | 사이클 makespan + 납기지연을 줄이는 탐색이 장기 리드타임과 어긋남 | Cyclic-GILS 대 Cyclic-VAA |
| L5 사이클 밖 정보 미사용 | 이전 사이클의 대기 화물, 곧 들어올 트럭을 보지 않음 | 상태 기반 정책과의 차이 |
| (계산 시간) | 사이클당 GILS 실행 시간 | `plan_ms_mean/max` |

## 4. 강화학습 설계

**MDP.** 결정 시점은 도어가 비어 있고 야드에 트럭이 있는 사건 시점이다. 행동 집합은
{야드 앞쪽 6대} × {빈 도어} × {목적지} ∪ {HOLD}, 보상은 다음 결정까지 적립된 비용의 음수이다.

**정책망.** 후보마다 24차원 특징(트럭: 종류·대기·납기 여유·유지 화물 비중·하역 시간, 목적지:
대기 화물·가장 오래된 화물 나이·미하역 화물·먼저 가져갈 운송 트럭 수·마지막 출발 이후 시간·수요
비중·야드 유입 화물, 도어: 중심성·대기 화물까지 이송 거리·예상 적재 대기, 전역 4개, 규칙 지시자)을
공유 MLP로 점수화한다. 시간은 트럭당 평균 작업량, 화물은 트럭당 평균 화물량으로 정규화해서
도어·목적지 수가 다른 규모에 그대로 적용된다(L은 학습에 쓰지 않고 일반화만 평가).

**학습 방법 세 가지**

1. PPO v1: FCFS-VAA 모방(BC)으로 시작 → PPO(엔트로피 0.01). 조정 점수가 BC(1.916)보다 나빠짐(2.92까지). 처음부터 학습한 PPO는 70 이상으로 불안정.
2. PPO v2: critic 예열 10회, 전역 상태 14차원, 엔트로피 0, 클리핑 0.1, 학습률 1e-4. 안정적이지만
   80회 반복 동안 BC 정책에서 거의 움직이지 않음(1.9164–1.9168).
3. 시뮬레이션 기반 정책 개선(Rollout) + 증류(근사 정책 반복):
   후보(앞 트럭 × 모든 목적지, 다음 두 트럭의 규칙 행동, HOLD)마다 현재 상태를 8번 복제해
   1·SLA 시간 동안 FCFS-VAA로 진행하고(공통 난수), 적립 비용이 가장 작은 행동을 고른다.
   이 결정을 DAgger로 정책망에 증류한다(`experiments/stream_api_train.py`).

학습 하이퍼파라미터와 시드 분리(train / tuning / test)는
[stream_experiment_setup.md](stream_experiment_setup.md) 4절과 6절에 있다.

| 한계 | 판정 | 근거 |
|---|---|---|
| L1 사이클 강제 | 확인 | 사이클이 다 모일 때까지 트럭당 평균 128(S) / 236(M) / 266(L) 대기. Cyclic-GILS의 야드 대기 234/533/895는 FCFS-VAA 34.5/112/386의 2.3–6.8배 |

| L3 정적 계획-실행 불일치 | 확인 | 계획대로 실행(strict)하면 모든 셀에서 대기열이 커져 +986–2,583%, 시간 상한까지 미배송 화물 발생. 유연 실행 보정 후에도 +31% |

해 표현이 연속 운영에 맞지 않아 실시간 상태 기반 디스패칭보다 31% 이상 나쁘다.

### 5.3 강화학습 결과

- **PPO는 실패했다.** v1은 BC 정책을 망가뜨렸고(조정 점수 1.92 → 2.92), v2는 안정적이지만 BC 정책에서
  움직이지 않아 시험 결과가 FCFS-VAA와 같다(보류 비율 0). 후보 수가 많고 보상 잡음이 커서, 결정 하나의
  효과가 긴 시간에 걸쳐 섞이는 이 환경에서 정책 경사의 신호가 약했던 것으로 본다.
- **시뮬레이션 기반 정책 개선(Rollout)은 크게 효과가 있다.** 모든 시험 스트림(90/90)에서 FCFS-VAA보다
  좋고 평균 −16.8%이며, 학습하지 않은 L에서 개선 폭이 가장 크다(−20.6%). 납기지연을 특히 줄인다(L 193 → 27.6).
  대가는 결정당 평균 28–227 ms(최대 0.73초)의 계산이다. 트럭 도착 간격(약 64–99 시간 단위)에 비하면 실시간
  운영에 충분히 짧다.
- **증류한 정책망(RL-API)은 Rollout 이득의 약 2/3를 1 ms 이하로 얻는다**(−10.6%, 결정 0.2–0.4 ms).
  S/M에서는 Rollout과의 차이가 작지만(−11.7/−11.3% 대 −13.4/−16.5%), 학습하지 않은 L에서는 차이가
  크다(−8.9% 대 −20.6%). 특히 L-uniform 저부하 두 셀에서는 FCFS-VAA보다 나쁘다.
- **RL이 배운 것**(`outputs/stream_behavior.txt`, tuning): 목적지별 운송 트럭 배분을 화물량에 맞추고(L1 거리
  0.279 → 0.048), 약 12%의 결정에서 보류하며, 약 20%의 결정에서 규칙과 다른 목적지를 고르고, 공차 출고를
  줄인다. 반면 도어 막힘(운송 트럭이 화물을 기다리며 도어를 점유하는 시간, 도어 시간의 약 27%)은 줄이지 못했다.

### 5.4 비교 기준 확장: VAA만, 원 논문 SA-RL5, 사이클 최적해, 다른 디스패칭 규칙 (S·M)

VAA-GILS 외의 기준에서도 결론이 유지되는지 확인하려고 비교 방법을 넷 추가했다. L은 사이클 CP-SAT 계산이 커서 제외했다
(중단 전 L Cyclic-CPSAT 7개는 `outputs/stream_eval_cpsat_L_partial.jsonl`에 따로 보관).

- `Cyclic-SA-RL5`: 사이클마다 원 논문의 SA-RL5(Q-learning 이웃 선택 + SA 수락, 납기지연 포함 목적식 = Extended-SA-RL5) 1,000회
- `Cyclic-CPSAT`: 사이클마다 CP-SAT(10초 제한). 사이클 98.7%(S) / 99.8%(M)에서 최적 증명 → 사이클별 최적해 기준
- `SPT-VAA`: 앞 6대 중 처리시간이 가장 짧은 트럭 먼저(목적지·도어 규칙은 FCFS-VAA). 납기가 모두 도착 + 같은 SLA라 EDD는 FCFS와 같아 생략
- `Random`: 앞 6대 트럭, 빈 도어, 목적지를 무작위로 선택(보류 없음)

해석

- 사이클을 개선 탐색으로 푸는 것(VAA → SA-RL5)은 연속 운영에서도 10–25% 이득이 있다. 그러나 그 이상(SA-RL5 → GILS → 최적해)은
  정적 목적값에서 0.6%의 차이가 있어도 연속 운영 성능을 1% 안에서만 바꾼다. S에서는 사이클 최적해가 GILS보다 0.6% 나빴다.
- 따라서 사이클 방식의 손실(+28–33%)은 풀이기가 아니라 사이클 틀(L1–L3)에서 나오며, 사이클별 최적해로도 상태 기반 RL 정책보다
  약 30% 나쁘다. L4 기각이 더 강하게 확인된다.
- SPT는 FCFS와 차이가 거의 없고(±1%), Random은 2–2.4배 나빠 결정 방식이 성능을 크게 좌우함을 보인다.

### 5.5 튜닝한 규칙과 절대 기준 (SCI(E) 계획 1개월차, S·M 60개 스트림)

[scie_plan_stream.md](scie_plan_stream.md) E1·E2의 첫 작업. RL 정책이 잘 튜닝한 규칙과 같은 정보의 선형 정책도 넘는지, 최적에서 얼마나 먼지 본다.

**추가한 비교 대상** (둘 다 train 풀 36개 스트림에서 교차 엔트로피 탐색, 최종 선택은 tuning 셋 = RL 체크포인트 선택과 같은 절차)

- `Tuned-Rule`: 해석 가능한 특징 9개(야드 대기, 납기 여유, 자기 화물 비중, 목적지 대기 화물, 가장 오래된 화물 나이, 마지막 출발 이후 시간,
  출고트럭 여부, 트럭 작업량, 하역 중 화물)의 가중합 + 보류 임계값(`PriorityRulePolicy`). tuning 셋 1.770
- `Tuned-Linear`: RL 정책망과 **같은 24개 후보 특징**(보류 포함)의 선형 점수(`LinearScorePolicy`). 초기값은 FCFS-VAA와 정확히 같음. tuning 셋 1.802
- 참고 tuning 셋 점수: FCFS-VAA 1.916, RL-API 1.680, Rollout 1.627

**절대 기준**: `stream_lower_bound`(대기 없음, 도어 경합 없음, 모든 트럭이 모든 목적지의 운송 트럭이 될 수 있다는 완화, 실제 도착 순서 사용).
정책과 무관하며 모든 정책의 목적값 이하임을 테스트로 확인. 관측 최선 = 스트림별 모든 방법 중 최선.

| 방법 | FCFS-VAA 대비 | 관측 최선 대비 | 하한 대비 | 보류 비율 | 결정 시간(ms) |
|---|---:|---:|---:|---:|---:|
| FCFS-VAA | 0 | +18.6% | +168% | 0 | 0.01 |
| Tuned-Linear (같은 정보, 선형) | −6.3% | | | 0 | 0.16 |
| Tuned-Rule | −6.8% | +10.0% | +148% | 0 | 0.04 |
| RL-API | −11.5% | +4.5% | +136% | 0.13 | 0.24 |
| Rollout | −15.0% | +0.1% | +126% | 0.10 | 59 |

(Tuned-Linear의 관측 최선·하한 대비 값은 `outputs/stream_eval_summary.txt` 참고)

짝지은 Wilcoxon: RL-API vs Tuned-Rule −5.0%(RL-API가 56/60, p = 9.6e-9), RL-API vs Tuned-Linear −5.6%(55/60, p = 6.1e-10),
Tuned-Rule vs Tuned-Linear −0.6%(36/60, p = 0.032).

해석

- 계획의 판정("튜닝한 규칙 ≈ RL-API이면 학습 정책 주장 축소")에 걸리지 않는다. RL-API는 잘 튜닝한 규칙보다 약 5% 좋다.
- **같은 정보를 쓰는 선형 정책도 RL-API에 못 미친다**(오히려 9개 특징 규칙과 비슷). RL-API의 우위는 정보량이 아니라 비선형 판단에서
  나온다. 두 튜닝 정책 모두 보류를 쓰지 않는 쪽으로 수렴했고(선형 점수로는 "언제 기다릴지"를 표현하기 어려움), RL-API는 결정의 13%에서
  보류한다.
- 하한은 유효하지만 느슨하다(Rollout도 하한의 1.96–2.71배, 평균 2.26배). 운송 트럭이 목적지 하나만 맡는 제약과 묶음 적재 대기가 빠졌기
  때문이며, 이를 넣으면 사후 최적 문제와 거의 같아진다. 따라서 하한은 "최적성 격차의 상한"으로만 보고하고, 절대 기준은 사후 최적
  기준해(일반화 모형, 소형 구간 CP-SAT)로 만든다(다음 작업).
- 계산 메모: Tuned-Linear 튜닝은 보류가 많은 가중치에서 대기열이 폭주해 약 49시간 걸렸다(첫 실행 8회 + 재개 15회, 재개 때 학습 스트림의
  시간 상한을 20 → 3 SLA로 낮춤, 기록 `outputs/stream_rl/tuned_linear*.log.jsonl`).

### 5.6 롤링 호라이즌, 계산을 늘린 Rollout, 정보 가치, 사후 최적 (2026-10-15~26)

**새로 만든 것**

- `stream/hindsight.py`: 일반화 정적 모형(목적지당 운송 트럭 여러 대)의 CP-SAT 모형.
  - 시뮬레이터 규칙을 그대로 옮겼다: 최초 claim 규칙, 이송시간, 도어 점유, 종료 sweeper.
  - 정책의 일정을 고정하면 목적값이 시뮬레이터와 정확히 일치한다(검증 60/60, 테스트 포함).
  - `event_aligned`: 도킹을 도착·출발 시점으로 제한한다. 정책과 같은 행동 공간에서 미래를 다 아는 최적이다.
  - 자유 시각 형태: 그보다 넓은 완화라서 하한으로 쓴다.
- `stream/finite.py`: 유한 교대.
  - 스트림의 첫 n대만 쓰고, 빈 상태에서 시작한다.
  - 운송 트럭이 남지 않은 화물은 마지막 출발 후 가상 회수 트럭(sweeper)이 싣는다.
  - 온라인 정책은 교대 길이는 알지만 도착은 모른다.
- `stream/rolling.py`: 롤링 호라이즌.
  - 현재 상태(도킹 트럭 고정, 야드 앞 8대, 남은 화물의 출처)를 위 모형으로 CP-SAT 1초 동안 풀고, 지금 도킹할 트럭만 실행한다.
  - 미래 도착은 가정하지 않는다. 남은 화물의 미래 운송 트럭 대기를 나타내는 종료 지연은 tuning 셋에서 골랐다:
    {0.5, 1, 1.5, 2, 3} → 1.5, 점수 4.04 / 2.14 / 1.81 / 1.84 / 1.88. 이 값에 매우 민감하다.
- `fork(oracle=True)`와 `Rollout-Oracle`: 실제 미래 도착을 보는 Rollout이다. 정보 가치 측정용이며 관측 최선에서 제외한다.
- `Rollout-32`: 표본 32, 구간 2 SLA. 기존 Rollout은 표본 8, 구간 1 SLA다.

**연속 스트림 결과 (시험 S·M 60개)**

| 방법 | FCFS-VAA 대비 | 관측 최선 대비 | 결정 시간(ms) |
|---|---:|---:|---:|
| Cyclic-CPSAT | +29.6% | +55.0% | 75 |
| FCFS-VAA | 0 | +19.2% | 0.01 |
| Rolling-CPSAT | −5.2% | +12.8% | 242 (해 없음 → FCFS 대체 11%, 보류 22%) |
| Tuned-Rule | −6.8% | +10.5% | 0.04 |
| RL-API | −11.5% | +5.1% | 0.2 |
| Rollout-32 | −14.2% | +1.5% | 786 |
| Rollout | −14.9% | +0.6% | 59 |
| Rollout-Oracle (참고) | −18.3% | −3.4% | 15 |

짝지은 Wilcoxon:
- Rolling vs FCFS −5.2%(48/60, p = 6.1e-6)
- Rolling vs Tuned-Rule +1.8%(Rolling이 24/60, p = 0.014)
- RL-API vs Rolling −6.5%(56/60, p = 7.1e-11)
- Rollout-32 vs Rollout +0.9%(28/60, p = 0.12)
- Rollout-Oracle vs Rollout −4.0%(60/60, p = 1.7e-11; 부하 0.5/0.6/0.7에서 −3.9/−4.0/−4.0%)

해석:
- 문헌의 표준 비교 대상인 롤링 호라이즌 재최적화는 FCFS보다 좋지만, 튜닝한 규칙에도 미치지 못한다.
  - 현재 정보만으로 최적화하면 남은 화물이 미래 운송 트럭을 기다리는 비용을 상수 하나로밖에 나타낼 수 없다.
  - 그래서 결과가 이 값에 크게 흔들린다.
- 계산을 4배로 늘려도 Rollout은 좋아지지 않는다. FCFS를 기본 정책으로 한 번 개선하는 방식은 이미 한계에 있고, 관측 최선 기준은 안정적이다.
- 완벽한 도착 예측의 가치는 이 방법에서 약 4%로, 부하와 무관하다.

**사후 최적 비교 (유한 S 인스턴스, hindsight 풀 시드 500000+, `outputs/stream_hindsight_summary.txt`)**

| 방법 | n=6 (30개) vs HS-event | n=10 (12개) vs HS-event |
|---|---:|---:|
| FCFS-VAA | +14.8% | +24.3% |
| Tuned-Rule | +14.2% | +22.5% |
| Tuned-Linear | +17.5% | +26.3% |
| RL-API | +17.0% | +16.5% |
| Rollout | +8.0% | +10.3% |
| Rollout-32 | +8.3% | +9.4% |
| Rollout-Oracle | +8.2% | +6.1% |

- HS-event = 사건 정렬 CP-SAT로 찾은 최선(실현 가능, 300/600초).
  - n=6에서는 30개 중 17개가 최적으로 증명됐다(자유 시각 완화도 17개 증명, 평균 2초).
  - n=10에서는 증명된 것이 없어 HS-event는 찾은 최선이다. 따라서 진짜 최적과의 격차는 이 표보다 클 수 있다.
- 어떤 정책도 HS-event보다 좋은 인스턴스는 없었다.
- 분해: Rollout에서 Rollout-Oracle로 가는 정보 기여는 n=6에서 −0.3%(p = 0.46), n=10에서 −3.5%(11/12, p = 0.0049)다.
  Rollout-Oracle에서 HS-event까지 남는 격차는 n=6에서 +8.1%(30/30), n=10에서 +6.2%(12/12)다.
  - 즉 Rollout과 사후 최적의 격차 8–10% 중 정보로 설명되는 것은 0–3.5%다.
  - 나머지 6–8%는 미래를 알아도 한 단계 개선으로는 닫히지 않는 최적화 격차다. 정책 반복 계열 방법(사후 학습, 반복 증류)의 여지가 여기에 있다.
- RL-API는 n=6에서 FCFS보다 나쁘다. 연속 스트림으로만 학습해 교대 종료에 대한 판단이 없기 때문이다.
  유한 인스턴스는 끝 효과가 크므로 정책 순위보다는 격차 분해의 근거로만 쓴다.
- 자유 시각 하한은 증명되지 않은 인스턴스에서 매우 느슨하다(CP-SAT bound). 절대 하한으로는 n=6의 증명 결과만 쓴다.

### 5.7 사후 학습 시도: 실제 미래를 보는 교사로 증류 (2026-10-26, tuning 셋)

[novel_methods_stream.md](novel_methods_stream.md)의 1순위 방법을 시험했다(Sinclair et al. 2022의 hindsight learning).

- 교사: 외생 도착의 실제 미래를 보는 Rollout(`--oracle`, 표본 1). 학습 정책은 여전히 현재 상태만 본다.
- 나머지 설정은 RL-API와 같다: DAgger 6라운드, train 풀, tuning 셋으로 체크포인트 선택.
- 레이블 두 가지: 교사의 최선 행동(hard), 또는 교사가 매긴 후보 행동별 비용의 softmax(soft, `--soft 0.5`).

| 교사 | 레이블 | 에피소드/라운드 | tuning J/work (낮을수록 좋음) |
|---|---|---:|---:|
| (BC = FCFS-VAA) | | | 1.916 |
| Rollout 표본 1 (미래 표본) | hard | 8 | 1.834 |
| 실제 미래 (oracle) | hard | 8 | 1.759 |
| 실제 미래 (oracle) | hard | 16 | 1.765 |
| 실제 미래 (oracle) | soft | 16 | 1.769 |
| Rollout 표본 8 | soft | 16 | 1.734 |
| **Rollout 표본 8 (= RL-API)** | hard | 16 | **1.680** |
| (교사 Rollout 표본 8 자체) | | | 1.627 |

판정: 사후 교사는 RL-API를 넘지 못한다(계획의 기준은 3% 이상 개선). 채택하지 않는다.

- 같은 표본 1개라도 미래 표본 대신 실제 미래를 쓰면 좋아진다(1.834 → 1.759). 정보는 레이블 질을 높인다.
- 그러나 표본 8개로 평균한 교사(1.680)에는 크게 못 미친다. 한 개의 실제 미래에 맞춘 최선 행동은 "다음 트럭이 언제 오는가"에 좌우된다.
  현재 상태만 보는 정책은 이를 알 수 없으므로 레이블이 잡음처럼 작용한다.
  사후 편향이 작다는 Exo-MDP 이론의 전제가 이 문제(묶음 적재 타이밍)에서는 성립하지 않는다.
- soft 레이블은 어느 교사에서도 hard보다 나빴다.
- 주의: 설정마다 학습 시드는 하나다. 라운드 간 tuning 점수 변동이 0.05 안팎이라 1.76 부근의 차이는 구분되지 않는다.
  RL-API와의 차이(0.08 이상)는 이보다 크다.

결론적으로 이 문제에서 학습 신호의 병목은 정보가 아니라 분산이다. 다음 후보는 최적화 계층을 넣은 정책(COAML, 2순위)과
해석 가능한 비교 대상인 LLM 진화 규칙(3순위)이다. 기록: `outputs/stream_rl/api_{hs,hs16,hs_soft,soft,r1}.stdout`.

## 6. 다음 단계

2026-10-12 기준 후속 제안(다음 RL 방법, MARL, 기준해 설계, 산업 데이터 조사)은

**연구 자체의 보강**

1. 증류 개선: 교사 점수를 소프트 레이블로 쓰기, 망 확대, 데이터 증가, 학습 규모에 L 포함 여부 비교,
   2라운드 이후 성능이 떨어진 원인(레이블 잡음, 분포 이동) 분석
2. 반복 정책 개선: 증류된 정책을 rollout의 기본 정책으로 다시 쓰는 다단계 근사 정책 반복
3. 도어 막힘 감소: 화물 준비 시각을 고려한 도어·순서 결정, 적재 시작 지연(보류) 행동의 세분화
4. 최적성 기준점: 유한 구간 사후 최적화(hindsight)나 하한으로 정책의 최적성 격차 추정

**외국 학술지 투고를 위해 필요한 것**

5. 더 강한 비교 대상: 운송 트럭 여러 대를 표현하도록 일반화한 롤링 호라이즌 재최적화(도어 가용 시각 포함),
   크로스도킹 문헌의 온라인 디스패칭 규칙, 다른 DRL 방법(제대로 튜닝한 PPO/DQN 변형)
6. 실험 규모: 셀당 스트림 5 → 20, SLA 계수·λ·병행 트럭 비율·도어 수 민감도, 특징 ablation
7. 모형 현실성 근거: 적재 용량, 출고트럭 시간표, 도착 과정 가정. 가능하면 산업 데이터 사례
8. 문헌 조사: 동적·온라인 크로스도킹 스케줄링과 RL 적용 연구(원문 모델 절까지 확인)
9. JKIIE 원고와의 관계 정리(인용, 차별점)와 지도교수 협의
