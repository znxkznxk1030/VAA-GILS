# 연속 도착 크로스도킹에서 VAA-GILS의 한계와 강화학습 (research/rl 브랜치)

JKIIE 원고의 정적 모형(|I| + |F| = |D|, 한 번의 닫힌 배치, makespan + λ·납기지연)을
트럭이 끝없이 도착하는 운영 환경(|I| + |F| ≫ |D|)으로 옮겼을 때, VAA-GILS가 어디서
무너지는지 측정하고, 강화학습(RL)이 그 한계를 메우는지 실험한다.

> 결과 수치는 `outputs/stream_eval_summary.txt`(시험 집합)와 `outputs/stream_rl/`
> (학습·조정 기록)에 있다. 이 문서의 표는 그 파일에서 옮긴 것이다.

## 0. 예비 결과: 도착 시각 불확실성만으로는 학습할 여지가 없다 (G0)

먼저 정적 모형을 그대로 두고 트럭 도착 시각만 실시간으로 드러나게 했다
(`crossdock_solver/dynamic/`, `experiments/dynamic_gate.py`, tuning pool).
재계획을 전혀 하지 않는 StaticPlan도 사후 최적(Hindsight)보다 평균 0.3–0.6%만 나빴고,
Rolling-GILS는 0.14–0.45%였다. 무작위 정책은 10–35% 나빠서 배정 결정 자체는 중요하지만,
최적 배정이 도착 시각에 거의 영향을 받지 않는다. 이 설정에서는 RL이 개선할 여지가 0.5% 미만이므로
문제 구조 자체를 바꾸었다(아래).

## 1. 연속 도착 모형

모형, 파라미터, 목적식, 실험 설계, 계산 환경의 전체 내용은
[stream_experiment_setup.md](stream_experiment_setup.md)에 있다. 요약하면 다음과 같다.

- 트럭이 포아송 흐름으로 끝없이 도착하고(병행 트럭 2/3), 도어가 비면 정책이 (트럭, 도어, 목적지)를
  고르거나 보류한다. 병행 트럭의 부분 하역 → 운송 트럭 전환 구조는 정적 모형과 같다.
- 운송 트럭은 적재 시작 시점에 이미 도킹한 트럭의 해당 목적지 화물을 모두 가져가고, 하역·이송이 끝날 때까지 기다린다.
- 목적식은 J = 화물 단위당 평균 리드타임 + λ · 트럭당 평균 납기지연(λ = 1)이고, 규모 간 비교는 J/work로 한다.

## 2. VAA-GILS를 연속 흐름에 적용하는 방법

VAA-GILS의 해 표현은 "목적지마다 운송 트럭 정확히 한 대"이다. 원 방법을 바꾸지 않고 쓰려면
도착 순서대로 |D|대씩 묶어 한 사이클을 정적 인스턴스(|I_c| + |F_c| = |D|)로 만들고, 사이클마다
VAA 또는 VAA-GILS(1,000회, 논문 최종 엔진)로 풀어야 한다(`CyclicPlanPolicy`).

- `Cyclic-GILS-strict`: 계획한 도어가 빌 때까지 기다리며 계획대로 실행
- `Cyclic-GILS` / `Cyclic-VAA`(adaptive): 목적지와 순서는 계획을 따르되, 계획 도어가 바쁘면 가장
  가까운 빈 도어를 쓰고, 출고트럭은 같은 사이클의 해당 목적지 화물 병행 트럭이 모두 도킹한 뒤
  보낸다(정적 모형의 "운송 트럭은 이송 화물을 모두 기다린다"를 지키도록). VAA-GILS에 공정하도록
  추가한 실행 보정이다.

## 3. 한계 가설과 측정 지표

| 한계 | 메커니즘 | 측정 |
|---|---|---|
| L1 사이클 강제 | |D|대가 모일 때까지 계획을 못 함 | 사이클 형성 대기(`cycle_wait`) |
| L2 운송 빈도 경직 | 사이클마다 목적지별 운송 트럭이 정확히 1대 → 화물량과 무관하게 1/|D| | skewed 수요에서 비용 증가, 목적지별 운송 트럭 비중 대 화물 비중 |
| L3 정적 계획-실행 불일치 | 정적 모형은 모든 도어가 비어 있고 사이클 병행 트럭이 동시에 도킹한다고 가정 | strict 실행의 비용과 안정성 |
| L4 대리 목적식 | 사이클 makespan + 납기지연을 줄이는 탐색이 장기 리드타임과 어긋남 | Cyclic-GILS 대 Cyclic-VAA |
| L5 사이클 밖 정보 미사용 | 이전 사이클의 대기 화물, 곧 들어올 트럭을 보지 않음 | 상태 기반 정책과의 차이 |
| (계산 시간) | 사이클당 GILS 실행 시간 | `plan_ms_mean/max` |

## 4. 강화학습 설계

**MDP.** 결정 시점은 도어가 비어 있고 야드에 트럭이 있는 사건 시점이다. 행동 집합은
{야드 앞쪽 6대} × {빈 도어} × {목적지} ∪ {HOLD}, 보상은 다음 결정까지 적립된 비용의 음수이다.

**정책망.** 후보마다 24차원 특징(트럭: 종류·대기·납기 여유·유지 화물 비중·하역 시간, 목적지:
대기 화물·가장 오래된 화물 나이·미하역 화물·먼저 가져갈 운송 트럭 수·마지막 출발 이후 시간·수요
비중·야드 유입 화물, 도어: 중심성·대기 화물까지 이송 거리·예상 적재 대기, 전역 4개, 규칙 지시자)을
공유 MLP로 점수화한다. 시간은 트럭당 평균 작업량, 화물은 트럭당 평균 화물량으로 정규화해서
도어·목적지 수가 다른 규모에 그대로 적용된다(L은 학습에 쓰지 않고 일반화만 평가).

**학습 방법 세 가지**

1. PPO v1: FCFS-VAA 모방(BC)으로 시작 → PPO(엔트로피 0.01). 조정 점수가 BC(1.916)보다 나빠짐(2.92까지). 처음부터 학습한 PPO는 70 이상으로 불안정.
2. PPO v2: critic 예열 10회, 전역 상태 14차원, 엔트로피 0, 클리핑 0.1, 학습률 1e-4. 안정적이지만
   80회 반복 동안 BC 정책에서 거의 움직이지 않음(1.9164–1.9168).
3. 시뮬레이션 기반 정책 개선(Rollout) + 증류(근사 정책 반복):
   후보(앞 트럭 × 모든 목적지, 다음 두 트럭의 규칙 행동, HOLD)마다 현재 상태를 8번 복제해
   1·SLA 시간 동안 FCFS-VAA로 진행하고(공통 난수), 적립 비용이 가장 작은 행동을 고른다.
   이 결정을 DAgger로 정책망에 증류한다(`experiments/stream_api_train.py`).

학습 하이퍼파라미터와 시드 분리(train / tuning / test)는
[stream_experiment_setup.md](stream_experiment_setup.md) 4절과 6절에 있다.

| 한계 | 판정 | 근거 |
|---|---|---|
| L1 사이클 강제 | 확인 | 사이클이 다 모일 때까지 트럭당 평균 128(S) / 236(M) / 266(L) 대기. Cyclic-GILS의 야드 대기 234/533/895는 FCFS-VAA 34.5/112/386의 2.3–6.8배 |

| L3 정적 계획-실행 불일치 | 확인 | 계획대로 실행(strict)하면 모든 셀에서 대기열이 커져 +986–2,583%, 시간 상한까지 미배송 화물 발생. 유연 실행 보정 후에도 +31% |

해 표현이 연속 운영에 맞지 않아 실시간 상태 기반 디스패칭보다 31% 이상 나쁘다.

### 5.3 강화학습 결과

- **PPO는 실패했다.** v1은 BC 정책을 망가뜨렸고(조정 점수 1.92 → 2.92), v2는 안정적이지만 BC 정책에서
  움직이지 않아 시험 결과가 FCFS-VAA와 같다(보류 비율 0). 후보 수가 많고 보상 잡음이 커서, 결정 하나의
  효과가 긴 시간에 걸쳐 섞이는 이 환경에서 정책 경사의 신호가 약했던 것으로 본다.
- **시뮬레이션 기반 정책 개선(Rollout)은 크게 효과가 있다.** 모든 시험 스트림(90/90)에서 FCFS-VAA보다
  좋고 평균 −16.8%이며, 학습하지 않은 L에서 개선 폭이 가장 크다(−20.6%). 납기지연을 특히 줄인다(L 193 → 27.6).
  대가는 결정당 평균 28–227 ms(최대 0.73초)의 계산이다. 트럭 도착 간격(약 64–99 시간 단위)에 비하면 실시간
  운영에 충분히 짧다.
- **증류한 정책망(RL-API)은 Rollout 이득의 약 2/3를 1 ms 이하로 얻는다**(−10.6%, 결정 0.2–0.4 ms).
  S/M에서는 Rollout과의 차이가 작지만(−11.7/−11.3% 대 −13.4/−16.5%), 학습하지 않은 L에서는 차이가
  크다(−8.9% 대 −20.6%). 특히 L-uniform 저부하 두 셀에서는 FCFS-VAA보다 나쁘다.
- **RL이 배운 것**(`outputs/stream_behavior.txt`, tuning): 목적지별 운송 트럭 배분을 화물량에 맞추고(L1 거리
  0.279 → 0.048), 약 12%의 결정에서 보류하며, 약 20%의 결정에서 규칙과 다른 목적지를 고르고, 공차 출고를
  줄인다. 반면 도어 막힘(운송 트럭이 화물을 기다리며 도어를 점유하는 시간, 도어 시간의 약 27%)은 줄이지 못했다.

### 5.4 비교 기준 확장: VAA만, 원 논문 SA-RL5, 사이클 최적해, 다른 디스패칭 규칙 (S·M)

VAA-GILS 외의 기준에서도 결론이 유지되는지 확인하려고 비교 방법을 넷 추가했다. L은 사이클 CP-SAT 계산이 커서 제외했다
(중단 전 L Cyclic-CPSAT 7개는 `outputs/stream_eval_cpsat_L_partial.jsonl`에 따로 보관).

- `Cyclic-SA-RL5`: 사이클마다 원 논문의 SA-RL5(Q-learning 이웃 선택 + SA 수락, 납기지연 포함 목적식 = Extended-SA-RL5) 1,000회
- `Cyclic-CPSAT`: 사이클마다 CP-SAT(10초 제한). 사이클 98.7%(S) / 99.8%(M)에서 최적 증명 → 사이클별 최적해 기준
- `SPT-VAA`: 앞 6대 중 처리시간이 가장 짧은 트럭 먼저(목적지·도어 규칙은 FCFS-VAA). 납기가 모두 도착 + 같은 SLA라 EDD는 FCFS와 같아 생략
- `Random`: 앞 6대 트럭, 빈 도어, 목적지를 무작위로 선택(보류 없음)

해석

- 사이클을 개선 탐색으로 푸는 것(VAA → SA-RL5)은 연속 운영에서도 10–25% 이득이 있다. 그러나 그 이상(SA-RL5 → GILS → 최적해)은
  정적 목적값에서 0.6%의 차이가 있어도 연속 운영 성능을 1% 안에서만 바꾼다. S에서는 사이클 최적해가 GILS보다 0.6% 나빴다.
- 따라서 사이클 방식의 손실(+28–33%)은 풀이기가 아니라 사이클 틀(L1–L3)에서 나오며, 사이클별 최적해로도 상태 기반 RL 정책보다
  약 30% 나쁘다. L4 기각이 더 강하게 확인된다.
- SPT는 FCFS와 차이가 거의 없고(±1%), Random은 2–2.4배 나빠 결정 방식이 성능을 크게 좌우함을 보인다.

2026-10-12 기준 후속 제안(다음 RL 방법, MARL, 기준해 설계, 산업 데이터 조사)은

**연구 자체의 보강**

1. 증류 개선: 교사 점수를 소프트 레이블로 쓰기, 망 확대, 데이터 증가, 학습 규모에 L 포함 여부 비교,
   2라운드 이후 성능이 떨어진 원인(레이블 잡음, 분포 이동) 분석
2. 반복 정책 개선: 증류된 정책을 rollout의 기본 정책으로 다시 쓰는 다단계 근사 정책 반복
3. 도어 막힘 감소: 화물 준비 시각을 고려한 도어·순서 결정, 적재 시작 지연(보류) 행동의 세분화
4. 최적성 기준점: 유한 구간 사후 최적화(hindsight)나 하한으로 정책의 최적성 격차 추정

**외국 학술지 투고를 위해 필요한 것**

5. 더 강한 비교 대상: 운송 트럭 여러 대를 표현하도록 일반화한 롤링 호라이즌 재최적화(도어 가용 시각 포함),
   크로스도킹 문헌의 온라인 디스패칭 규칙, 다른 DRL 방법(제대로 튜닝한 PPO/DQN 변형)
6. 실험 규모: 셀당 스트림 5 → 20, SLA 계수·λ·병행 트럭 비율·도어 수 민감도, 특징 ablation
7. 모형 현실성 근거: 적재 용량, 출고트럭 시간표, 도착 과정 가정. 가능하면 산업 데이터 사례
8. 문헌 조사: 동적·온라인 크로스도킹 스케줄링과 RL 적용 연구(원문 모델 절까지 확인)
9. JKIIE 원고와의 관계 정리(인용, 차별점)와 지도교수 협의
